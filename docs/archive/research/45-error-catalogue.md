## `type` URI

| option | form | for | against |
|---|---|---|---|
| **A** | `https://aruvii.ai/errors/<kebab-code>` | absolute URI as RFC 9457 3.1.1 recommends; same identifier on every install; can later serve a docs page | needs a domain the project owns and keeps; a URI that 404s for years teaches clients to ignore it |
| **B** | `/errors/<kebab-code> (relative)` | self-hosted: resolves against the customer's own host, so the bundled UI can serve the explanation page offline | RFC 9457 3.1.1: relative type URIs resolve against the document base and some clients mishandle them; the identifier differs per install, so clients must compare the code, not the type |

**Recommendation:** A, if the project owns aruvii.ai; else the URN form urn:aruvii:error:<kebab-code> (RFC-valid, non-dereferenceable, same on every install). Not B. Clients branch on `code`, never on `type`.

Derivation: type = base + code.toLowerCase().replace('_','-'); title = ErrorCode.title (fixed per code, RFC: same for every occurrence); detail = the template filled; instance = request path; extensions: code (UPPER_SNAKE), traceId, plus errors[] for VALIDATION_FAILED and Retry-After header for 429/503.

## ErrorCode → kind → status

```
use case ──► sealed outcome ──► Failure{code(), args()} ──► ONE mapper ──► ProblemDetail
                                                              status = code.kind().status()
                                                              + type · title · detail · instance · code · traceId
bug / infra ──► exception ──► GlobalExceptionHandler ──► INTERNAL_ERROR (500, generic detail)
filter chain (401 entry point · 403 denied handler · 429 rate filter) ──► same ProblemDetail writer
```

| kind | status | meaning |
|---|---|---|
| `validation` | 400 | the request is wrong; the caller fixes it |
| `unauthenticated` | 401 | no identity, or the identity is not valid |
| `forbidden` | 403 | identity known, RBAC says no |
| `not_found` | 404 | the addressed resource does not exist (or the caller may not see it) |
| `conflict` | 409 | duplicate, in use, stale, or the resource is in the wrong state |
| `content_blocked` | 422 | the content was understood and refused by a guardrail |
| `limited` | 429 | rate, budget, quota or step limit reached |
| `unexpected` | 500 | a bug or infra fault; generic detail, never the raw message |
| `upstream_failed` | 502 | a system we call (LLM, MCP, SMTP, DB, cert host) failed or refused us |
| `unavailable` | 503 | PROPOSED, outside the decided table: our own dependency is down, retry later |
| `upstream_timeout` | 504 | a system we call did not answer in time |

enum ErrorCode(Kind kind, String title, String detailTemplate, boolean retryable); enum Kind(int status). Status is never stored per code: ErrorCode.status() = kind.status(). Severity is derived from kind (4xx -> INFO/WARN, 5xx -> ERROR) instead of stored.

**SSE:** channel=sse codes travel as ChatResponseEvent.ErrorEvent{code, detail, traceId}; their status is the HTTP status the same failure would have, kept so the catalogue stays uniform.

**Wire `code`:** UPPER_SNAKE enum name in `code` (was kebab slug). Breaks the UI's only code branch, 'rag-top-k-invalid' (aruvii-ui features/tools/tool-detail.component.ts:33) and the 'auth-forbidden' fallback (core/auth.interceptor.ts:48-53). The kebab form survives inside `type`.
