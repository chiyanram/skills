## pstack — `scratchpad/plugins/pstack`

- **Router plus playbooks.** `skills/poteto-mode/SKILL.md` matches the task to a playbook (`playbooks/bug-fix.md`, `feature.md`, `refactoring.md` and others) and makes the agent copy the playbook's steps "in verbatim" into a todo list. A skipped step stays in the list with a `skip:` line.
- **Index, then leaf.** poteto-mode carries a one-line "applies when…" entry for each principle. The agent must read the leaf `principle-*/SKILL.md` before citing it ("Cite only principles whose leaf SKILL.md you read"). Every leaf sets `disable-model-invocation: true`, so 45 of 47 skills add no description cost.
- **Review comes from model diversity, not personas.** `skills/interrogate/SKILL.md` gives one filled template (`references/reviewer-prompt.md`: intent + diff + `rubric.md` lenses + `code-quality-review.md`) to Opus, GPT and Grok, all read-only. [drift 2026-10-17: now two reviewers, Opus + Grok (#511), see research/64a] Findings raised by 2+ models count as the strongest signal. The lead then judges each finding (`references/lead-judgment.md`).
- **Model per role, set once per machine.** `setup-pstack` writes an always-applied rule with one line per role: code delegates use the fast model, judgment and prose use Opus. It also sets the budget tier.
- **Encode lessons in structure.** `principle-encode-lessons-in-structure` says: when you write the same instruction twice, turn it into a lint, flag, check or script, "Delete the instruction".

## firstmate — github.com/kunchenguid/firstmate

- **An "agent distro", with no installer.** The README says the cloned repo is the whole distro, and launching any supported harness in it creates the first mate. `CLAUDE.md` is only `@AGENTS.md`. `bin/fm-ensure-agents-md.sh` enforces that convention in every project it manages.
- **Skill descriptions are the trigger index.** `AGENTS.md` §13 says the descriptions are "the always-loaded trigger index". Agent-only skills (`.agents/skills/*`, `user-invocable: false`, `metadata.internal: true`) load only at named triggers. `AGENTS.md` ends with "Maintaining this file", which says point, don't repeat, prune rather than append.
- **Roles are set by a contract, not by loading a file.** A worker becomes a worker through its `FIRSTMATE_OP: v1 launch-brief` scaffold (`bin/fm-brief.sh`), not by reading `AGENTS.md`. The brief's `## Captain's intent` section becomes the reviewer's acceptance criteria. `.no-mistakes.yaml` sets `disable_project_settings: true`, so gate agents never take on the captain identity.
- **Review is a gate pipeline.** `no-mistakes` runs review → fix → document → test → lint, driven by the worker (`.agents/skills/validation-supervision`).
- **Remote is the same home over SSH.** `docs/remote-secondmates.md`: a whole firstmate home runs on an SSH host. `bin/fm-remote-inherit-push.sh` pushes an allowlist from one declared owner (`FM_INHERITABLE_CONFIG`) and fails closed when the two revisions differ.

## mattpocock/skills — github.com/mattpocock/skills

- **Single source of truth, measured in context load.** `skills/productivity/writing-for-agents/SKILL.md` says every always-loaded pointer "costs on every turn". It names duplication as a cost and moves material down a ladder (inline → sibling file → external), each step behind a context pointer.
- **Invocation is the one axis.** `.agents/invocation.md`: a user-invoked skill has no model-facing description and cannot be called by another skill. A model-invoked skill keeps rich trigger text. Dependencies are written as "Call the Skill tool with X", not as file cross-references.
- **Hard vs soft setup dependency.** ADR `.agents/adr/0001-…`: only `to-tickets`, `to-spec` and `triage` point at `/setup-matt-pocock-skills`. The other skills stay light on tokens. Per-repo answers live in `docs/agents/*.md`, the same pattern our repo already uses.
- **Two-axis review, never merged.** `skills/engineering/code-review/SKILL.md`: the Standards and Spec subagents run in parallel. The repo's standards override a fixed Fowler-smell baseline, and smells are "always a judgement call". Results are reported side by side and "Do not merge or rerank".
- **Three ways to install, one tree.** README: the plugin is a managed subscription, `npx skills add` gives editable copies, and `scripts/link-skills.sh` symlinks into `~/.claude/skills` so that `git pull` updates them.

## addyosmani/agent-skills — github.com/addyosmani/agent-skills

- **Skill / persona / command layering.** `docs/agents.md`: a skill is the how, a persona (`agents/code-reviewer.md` and others) is the who, a command is the when. Commands do the orchestrating. Personas do not call each other.
- **Fan-out review with a fixed merge.** `.claude/commands/ship.md` sends three personas in one turn. The main context merges them into Blockers / Recommended / Acknowledged risks / Rollback.
- **Shared checklists, one copy each.** `references/*-checklist.md` and `definition-of-done.md` are pointed at from skills. `.claude/rules/skills-contributing.md` (path-scoped to `skills/**`) says to "never duplicate content between skills". `docs/skill-anatomy.md` caps SKILL.md at 500 lines and prefers scripts, because script output costs context and the script itself does not.
- **The router hook is opt-in.** `hooks/session-start.sh` injects the `using-agent-skills` meta-skill. It is deliberately not wired for Claude Code or Codex, because they already route skills by description and a second router would sit on top.
- **One tree, several manifests, CI-validated.** `.claude-plugin/`, `.codex-plugin/` and `.agents/plugins/marketplace.json` all point at `skills/`. `.github/workflows/test-plugin-install.yml` runs `validate-skills.js`, the link validator and evals.

## Anthropic (official)

- **Memory** (code.claude.com/docs/en/memory): "target under 200 lines per CLAUDE.md file". `@imports` "don't reduce its context cost". Path-scoped rules load when a matching file is *read*. CLAUDE.md is "context, not enforced configuration", so must-happen rules go in a PreToolUse hook. The project-root CLAUDE.md survives `/compact`. `@AGENTS.md` in CLAUDE.md lets several tools share one file.
- **Skills** (…/skills): only the name and description load at startup, inside a listing budget of 1% of the context window (1,536 characters per description). `disable-model-invocation` hides the description. `skillOverrides: "name-only"` trims it. `context: fork` + `agent:` runs a skill in a subagent.
- **Subagents** (…/sub-agents): `skills:` preloads the **full** skill text (our rubric gets loaded twice when the agent then re-reads it). Other fields: `model`, `effort`, `maxTurns`, `omitClaudeMd: true`, `isolation: worktree`. Precedence runs managed > `--agents` > project > user > plugin.
- **Plugins** (…/plugins): one unit holding skills, agents, hooks and MCP. Project scope comes from the committed `.claude/settings.json`, but each machine still installs. Cloud sessions don't load local plugins. `--plugin-dir` loads a plugin without a marketplace.
- **Engineering blog posts.** Skills use progressive disclosure: metadata, then SKILL.md, then files ("discover and load dynamically"). Context engineering means the "smallest set of high-signal tokens", and subagents return 1–2k-token summaries. In the multi-agent research system, multi-agent uses ~15× chat tokens, effort-scaling rules sit in the prompt, Opus leads with Sonnet workers, and evaluation is "a single LLM call with a single prompt".

## Patterns that recur across ≥2 sources

1. **One canonical file, with other harness files pointing at it.** `CLAUDE.md` = `@AGENTS.md` (firstmate, Anthropic docs). Skill dirs are symlinked into the harness dirs (firstmate `.claude/skills`, mattpocock `link-skills.sh`). Several manifests sit over one `skills/` tree (addy, mattpocock).
2. **Always-loaded material is an index of pointers, and the body loads on demand.** Seen in pstack's router → leaf principles, firstmate's description trigger index, mattpocock's "context load" ladder, addy's `references/`, and Anthropic's progressive disclosure. The tool used everywhere is `disable-model-invocation` / `user-invocable: false` (pstack, firstmate, mattpocock, Anthropic).
3. **Repeated text becomes structure, and must-happen rules become hooks or scripts.** pstack has the encode-lessons principle. Anthropic says CLAUDE.md is context and hooks enforce. firstmate pins lint to the one owner CI uses. addy prefers scripts.
4. **Routing by task type.** pstack has 23 playbooks, mattpocock has `ask-matt` flows, and addy has intent → skill mapping plus commands. In each case the router *names* the steps or skills to run, and the agent copies them in rather than rereading a big rulebook.
5. **Review is a few lenses or axes, run in parallel, and judged by a lead.** None of the sources uses per-criterion receipts. pstack uses lenses with "use judgment" and model diversity. mattpocock uses 2 axes, repo standards over a smell baseline, and a 400-word cap. addy uses 3 personas and one merge. Anthropic uses a single rubric call and condensed returns. The cost controls are: hand over a diff command, not files; cap the output length; run reviewers read-only; and match the model to the role.
6. **Roles are defined by contract and orchestrated from above.** In firstmate a launch brief selects the role. In addy, commands orchestrate and personas do not call personas. In Anthropic's research system the lead gives each worker an objective, an output format and boundaries. A gate agent is kept out of the orchestrator's identity (firstmate `disable_project_settings`, Anthropic `omitClaudeMd`).
7. **Per-machine setup is written by a setup skill, separate from the shared tree.** pstack's `/setup-pstack` writes a model rule, mattpocock's `/setup-…` writes `docs/agents/*.md`, and firstmate keeps gitignored `config/crew-dispatch.json`. Shared files stay identical, and only local answers differ.
