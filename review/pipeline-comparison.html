The three differences

①An AI critic grades the design before you see it

factory

A critic scores the design and sends it back until it passes. You see only a design that has passed.

ours (G3 #16)

We removed spec-design-reviewer. Your /approved plus stage 8's acceptance-criteria citing cover it. Reviews cost about $2–2.8 each (R4).

  • humanlayer rpi keeps design approval with the human, in two steps: System Design, then Program Design.
  • Anthropic says a reviewer told to find gaps "will usually report some", which leads to over-engineering. Keep it scoped.
  • pstack uses its two-model review on plans as well as code. A finding raised by both models independently is the strongest signal.
  • your checklist lists "too much human review" as a mistake.

Switch when: the G11 metrics show designs you send back for reasons a checklist would have caught.

recommend Keep ours for now: you approve designs. Add one cheap AI pass at stage 5 only if the metrics show avoidable send-backs.

②Implementer and Tester as separate agents, in parallel packages

factory

The work is split into packages that run in parallel. In each package one agent writes code, a different agent writes the tests, and each has a critic.

ours (CP5, G6)

One developer per work item writes code and tests. Splitting the work means smaller separate work items, not parallel writers inside one item.

  • Anthropic best practices suggests one Claude writes the tests and another writes the code, so the code author can't bend the tests.
  • Anthropic long-running: "It is unacceptable to remove or edit tests" when an agent fixes code.
  • Cognition: keep writes single-threaded, because parallel writers make conflicting implicit decisions. Extra agents should only read or review.
  • Anthropic multi-agent: coding has fewer truly parallel tasks than research, and multi-agent costs about 15× the tokens.
  • ours today: a bug starts with a failing test; PIT on touched classes; the reviewer checks the tests; at most 2 builders per host (G26).

Switch when: reviews or PIT keep finding tests that were bent to pass the code.

recommend Keep one writer and no parallel packages. Large work becomes several small work items, which matches DORA's finding on small batches. Watch for bent tests; a separate test-writer is the fix if they appear.

③A review hub: 7 axes plus a second AI model

factory

Alignment, correctness, testing, security, architecture and production, plus a second model (Codex). Any axis can send the work back.

ours (G3 amended)

One fresh reviewer gives two verdicts and reads only the references for the changed paths. The lead validates each finding. At most 3 rounds.

  • pstack: "The adversarial signal comes from model diversity, not assigned personas." It runs 2 model families, down from 3 in #511.
  • industry (Anthropic, Cognition, GitHub): one fresh-context reviewer, advisory. No vendor runs parallel review axes by default.
  • mattpocock: 2 axes, reported separately so one cannot mask the other.
  • our P1 test (!230): one reviewer caught 5 of 7 real findings plus 5 new ones. It missed final and boundaries.

Switch when: merged work keeps showing defects that a second model family would have caught.

recommend Keep one reviewer, and add the second model family only on the floor lane (migration · security · API · dependency), where a miss costs most. Axes stay as sections of the one reviewer's checklist, not as separate agents.
